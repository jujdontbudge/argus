HOW THE CEILING WAS BEATEN, AND WHY IT IS NOT A FIX
------------------------------------------------------------------------------
#113 offered three options: checkpoint the drive, bound the Retro scan, or run
it detached. The drive was run DETACHED with polling — no production code was
changed to make this run pass. That choice is deliberate on two grounds:

  * The 10-minute ceiling is a property of how a worker invokes bash, not of
    the drive. Detaching is the only option that satisfies #113's acceptance
    criterion literally — ONE recorded run printing 16/16 and exiting 0.
    Checkpointing would have satisfied it by stitching two runs together,
    which is the opposite of what the criterion asks for.
  * Bounding the scan means changing `codex exec`'s invocation under ADR-0002's
    never-drop contract. That is a production design decision, and #113 says
    plainly: fix the harness, not the finding.

The only harness change is a stopwatch (`timed()`), which does not make the
drive faster — it makes a slow drive legible. That instrumentation is what
produced the timing evidence below, and the evidence reframes the blocker.

PRODUCTION HAS NO TIMEOUT ON THE LIVE RETRO BRAIN PATH
------------------------------------------------------------------------------
Read end to end, the chain is:

  RetroEye.scan
    -> judgeSignals            (src/eyes/retro/retro.ts:562)
    -> retryForever            (src/eyes/backpressure.ts:83)
    -> evaluateOnce            (src/eyes/retro/retro.ts:762)
    -> cap.acquire             (src/eyes/cap.ts:110)
    -> Brain.evaluate          (src/eyes/brain.ts:129)
    -> defaultSpawn            (src/eyes/brain.ts:108)  -> `codex exec`

Not one link carries a deadline:

  * `defaultSpawn` awaits `child.exited` with no timeout and no AbortSignal.
    A `codex exec` that never returns is awaited forever.
  * `createCodexBrain.evaluate` passes no deadline and `openRetro` exposes no
    knob to set one.
  * `retryForever` bounds FAILURES, not HANGS. Its stuck-alert (15 min) and its
    backoff only run when the operation THROWS. An attempt that never returns
    never throws, so the "eye-stuck" alert that exists precisely to make this
    loud NEVER FIRES. The one failure mode the alert cannot see is the one
    with no upper bound.
  * The daemon's shutdown `signal` is checked only BETWEEN attempts and during
    the backoff sleep (backpressure.ts:96,113). A hang is inside `operation()`,
    so SIGTERM sets the abort flag and nothing reads it: `argus watch retro`
    does not shut down until codex returns.
  * The watch loop tests `controller.signal.aborted` between ticks
    (src/watch.ts) — as does its own RSS-ceiling check. An eye hung in a brain
    call also stops enforcing its own memory ceiling.
  * Worst: the brain cap is MACHINE-WIDE and only 2 slots (ADR-0002), and a
    slot is reclaimed as stale only when its owning pid is DEAD. A hung call
    keeps the eye process alive, so the slot is never reclaimed. Two hung
    brain calls block every eye in every repo on the machine, permanently.

The codebase knows the pattern — `src/eyes/honcho/live-probe.ts` uses
`AbortSignal.timeout(500)` and `AbortSignal.timeout(10_000)`, and
`src/eyes/curator/usage.ts` breaks a lock held past a timeout. The brain path
is the inconsistency, exactly as the fixed temp path was in #107.

SPEC says nothing about what a live brain call costs or how long it may take.
