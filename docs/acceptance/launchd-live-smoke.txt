Finding
-------
The stale AUDIT.md §4 item 5 PATH claim is refuted by current source and this
live run. The installed plist carried an explicit PATH plus exact
ARGUS_CODEX_EXECUTABLE and ARGUS_GH_EXECUTABLE values. A tiny scratch entry
wrapper recorded the launchd process environment, ran `command -v` for both
tools, and then `exec`-ed the real Bun CLI. It resolved codex to
/Users/johansardar/.local/bin/codex and gh to /opt/homebrew/bin/gh without
invoking either command.

The run exposed two real coverage/behavior defects:

1. The old live gate launched a synthetic never-ending TypeScript script. It
   did not run the production supervisor daemon, watchers, `argus status`, or
   a launchd-list diff. Its pre-change baseline passed in 221 ms with only 3
   expect() calls. The replacement drives launchd -> real CLI -> production
   supervisor -> five real watchers -> real CLI status.
2. `argus status` labeled an alive watcher with no matching health report
   `running` and exited 0. A red-first public-CLI regression reproduced that
   exact output. Final code labels this state `degraded`, prints `watcher has
   not reported health`, and exits 1.

The final live drive deliberately configured an unsupported subscription model
inside the scratch repo. That made the real Reviewer, Digest and Retro fail
initialization without spending a subscription call. All three appeared as
`degraded`, their precise failure was visible, and `argus status` exited 1.

Teardown was clean: bootout returned 0; all five ticket-owned watcher PIDs were
gone; the scratch root (including its plist) was removed; 467 launchd service
labels existed before and after with an empty diff. A pre-existing real
`dev.argus.supervisor` and its five watcher processes existed before this
ticket's first launchd operation and remained after it. They were not signaled,
booted out, or otherwise changed. Consequently the ticket's global
`pgrep -f 'bin/bun.*cli\.ts watch' | wc -l` cannot honestly be 0 on this
machine; it is 5, all foreign to this ticket.
