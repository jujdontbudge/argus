5. what this run does NOT reach, and why that is a NOT RUN
------------------------------------------------------------------------------
An assistant row requires an inference provider that answers, and the only
providers that would answer on this machine are Johan's — his ChatGPT
subscription through openai-codex, or a key out of ~/.hermes/.env. Spending one
to make a test green is not in this ticket's gift, so the drive is built so it
CANNOT: the child environment carries no credential and the endpoint is a dead
loopback port.

So assistant-row persistence still rests on code-path plus live-DB evidence,
exactly as research §7 left it, and the `real` half stays NOT RUN until a real
profile exists. That half is the one that retires the caveat, and it starts
running by itself the first time Johan deploys Argus on a repo.

The scratch half asserts the caveat in its negative form — no assistant row
from a credential-free drive — which is falsifiable and was verified to fail:
substituting a Hermes that persists an assistant row without a provider turns
this red, and the failure diff carries the version string that changed the
answer.
