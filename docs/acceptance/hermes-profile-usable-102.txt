#102 — the Hermes profile `argus up` generates is usable through the name it writes

WHY THIS FILE EXISTS
  Before #102, no evidence under docs/acceptance/ demonstrated the GENERATED
  profile working. The last two Hermes drives (#82, #99) both ran against a
  default profile that had been bound BY HAND, because the generated one could
  not be selected. This file closes that gap: a real `argus up`, then the real
  `hermes` binary listing and selecting the name Argus produced.

THE LIMIT, AS MEASURED (not as remembered)
  hermes_cli/profiles.py:35
    _PROFILE_ID_RE = re.compile(r"^[a-z0-9][a-z0-9_-]{0,63}$")
  So: 64 characters, enforced as a REGEX BOUND, not a length check. The error
  says "Invalid profile name ... Must match ...", never "too long".
  Measured against hermes 0.16.0 with a scratch HERMES_HOME:
    len=63  rc=0  listed=1  Switched to: ...
    len=64  rc=0  listed=1  Switched to: ...
    len=65  rc=1  listed=0  Error: Invalid profile name ...
  Enforced at `profile use` (rc=1) and `profile info` (rc=1); `profile list`
  SILENTLY OMITS the profile at rc=0; `profile show` and `profile describe` do
  NOT validate at all and succeed on a name Hermes will not select.
  A second, unrelated 251-char limit lives in service_manager.py (s6 name_max)
  and is NOT the one that bites here.

DRIVE — real `argus up` in a scratch HOME (HOME/HERMES_HOME/CODEX_HOME/CLAUDE_CONFIG_DIR all scratch)
  $ cd <scratch>/Widget Kit && bun run src/cli.ts up
    Hermes profile: argus-widget-kit-1bb6189a3f642fbe
    length: 33  (limit 64)
